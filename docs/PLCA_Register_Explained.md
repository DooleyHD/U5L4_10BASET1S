## 1. 한 줄 요약

T1S는 여러 노드가 **선 한 쌍을 같이 쓰는 반이중 버스**입니다. 그냥 두면 CSMA/CD처럼 "먼저 말하는 사람이 임자"라서 충돌이 납니다.
**PLCA는 "순서표"를 만들어 충돌을 아예 없애는 방식**입니다.

- **ID 0번 노드(코디네이터)**가 `BEACON`이라는 "자, 한 바퀴 시작!" 신호를 보냅니다.
- 그 뒤 **ID 0 → 1 → 2 → … → NCNT-1** 순서로 **발언 기회(TO, Transmit Opportunity)**가 한 번씩 돌아갑니다.
- 내 차례에 보낼 게 있으면 보내고, 없으면 **TO 타이머(기본 3.2 µs)**만큼 기다렸다가 다음 ID로 넘어갑니다.
- 한 바퀴가 끝나면 코디네이터가 다시 BEACON을 보냅니다.

CAN의 중재(arbitration)와 비교하면: CAN은 "동시에 말하고 ID 낮은 쪽이 이긴다", PLCA는 "**아예 순서대로만 말한다**(라운드로빈)"입니다.

## 2. 샘플 코드가 PLCA를 설정하는 순서

`App_Init_ETNF()` → (Operation 모드 진입 후) `App_ConfigureT1SPHYSetting()` 호출: `App_sub.c:177-181`
이 호출은 `APP_COM_IF == T1S` 이고 모드가 PCS_LB / PMA_LB / NORMAL일 때만 들어갑니다. 현재 업로드본은 `APP_COM_MODE = APP_ETNF_NORMAL` (`App_ETNF_cfg.h:58`), `APP_COM_IF = APP_ETNF_T1S` (`App_ETNF_cfg.h:77`)라서 **실제로 실행됩니다.**

PHY 주소는 `APP_PLCA_ADDR = ETNF_PLCA_ADDR_DEFAULT` (`App_ETNF_cfg.h:120`) 입니다.

## 3. 레지스터별로 "PLCA 동작에 무엇을 하는지"

### 3.1 PLCACTRL0 (0x3FCA01) — PLCA 전원 스위치
| 비트 | 이름 | 샘플 값 | 설명 (UM 5.5.1.25) |
|---|---|---|---|
| 15 | EN | **1** (`App_sub.c:600`) | 1이면 PLCA 동작. 0이면 **일반 CSMA/CD**로 동작 |
| 14 | RST | 0 (`App_sub.c:601`) | 1을 쓰면 PLCA 블록만 리셋 (자동으로 0으로 돌아옴) |

리셋값은 `0x0000`, 즉 **아무것도 안 하면 PLCA는 꺼져 있습니다.**
EN=1이어도 MAC 쪽 MII에는 BEACON/COMMIT 신호가 보이지 않습니다. PHY 안에서 알아서 처리합니다.

### 3.2 PLCACTRL1 (0x3FCA02) — 순서표 (NCNT, ID)
| 필드 | 샘플 값 | 설명 (UM 5.5.1.26) |
|---|---|---|
| NCNT[15:8] | 코디네이터 **9** (`App_sub.c:616`) / 슬레이브 2 (`:619`) | 한 바퀴에 몇 개의 TO를 돌릴지. **코디네이터(ID 0)에서만 의미 있음.** 슬레이브는 0으로 둬도 됨 |
| ID[7:0] | 코디네이터 **0** (`App_sub.c:617`) / 슬레이브 **1** (`:620`) | 내 번호. **ID 0 = 코디네이터(BEACON 송신)** |

- 리셋값은 NCNT=8, ID=0xFF 입니다.
- 코드 `App_sub.c:619`의 주석은 "NCNT = 0x09"라고 적혀 있지만 실제 값은 0x02입니다. 슬레이브에서는 NCNT가 무시되므로 동작 영향은 없고 **주석만 틀렸습니다.**
- **주의:** `APP_COM_TYPE`는 `#if`의 두 갈래 모두 `APP_COM_MASTER` (`App_ETNF_cfg.h:69, 71`)입니다. 그래서 **지금 빌드는 항상 코디네이터(ID 0, NCNT 9)**로 동작합니다. 두 번째 보드를 슬레이브로 쓰려면 `App_ETNF_cfg.h:71`을 `APP_COM_SLAVE`로 바꿔 빌드해야 합니다.
- 버스에 ID 0이 **정확히 하나** 있어야 합니다. 두 보드 모두 코디네이터로 빌드하면 BEACON이 두 군데서 나와 `PLCADIAG.UNEXPB` / `BCNBFTO` 진단 비트가 켜집니다 (UM 5.4.4.1~2).

### 3.3 PLCATOTMR (0x3FCA04) — TO 타이머 (코드에서 안 씀 → 기본값 32 BT)
- TOTMR[7:0] = 한 노드에게 주는 **최소 대기 시간** (단위 BT = bit time, 10 Mb/s에서 1 BT = 100 ns).
- 기본값 `0x20` = **32 BT = 3.2 µs** (UM 5.5.1.28, 표준값).
- 의미: "내 차례인데 3.2 µs 안에 말을 시작하지 않으면 **다음 ID로 넘긴다**."
- 값을 키우면 → 긴 케이블(전파 지연)에 강해짐, 대신 빈 TO마다 시간이 더 버려짐.
- 값을 줄이면 → 사이클이 빨라짐, 대신 케이블이 길면 오동작.
- **버스의 모든 노드가 같은 값**이어야 합니다. UM CAUTION: IEEE 식 148-1로 계산할 때 왕복 전파 지연에 **2 BT(200 ns)를 더하라**고 합니다.

### 3.4 PLCABURST (0x3FCA05) — 버스트 모드 (코드에서 안 씀 → 꺼짐)
| 필드 | 리셋값 | 설명 (UM 5.5.1.29) |
|---|---|---|
| MAXBC[15:8] | **0** | 한 TO 안에서 **추가로** 보낼 수 있는 프레임 수. 0 = TO당 1프레임 |
| BTMR[7:0] | 0x80 = 128 BT (12.8 µs) | 버스트 중 다음 프레임을 MAC이 줄 때까지 기다리는 시간. **IFG(96 BT)보다 작으면 안 됨** |

샘플은 MAXBC=0이므로 **한 바퀴에 노드당 프레임 1개**입니다.
샘플은 TX 큐 4개에 프레임 4개를 넣으므로, 코디네이터는 **4바퀴(BEACON 4번)**에 걸쳐 1개씩 내보냅니다.

### 3.5 PLCAST (0x3FCA03) — PLCA가 실제로 돌고 있나? (코드에서 안 읽음)
- bit15 **PST** = 1이면 "선로에서 PLCA(BEACON)가 돌고 있음" (UM 5.5.1.27, IEEE 148.4.6).
- 샘플은 PST 대신 Clause 22 STATUS 레지스터(`App_sub.c:549-552, 635-637`)만 기다립니다. 이것은 **링크 상태**이지 **PLCA 동기 상태**가 아닙니다.
- PST=0인 동안은 PLCA가 아직 동기를 못 잡은 상태라 **충돌 검출이 항상 켜져 있습니다** (T1STWEAKS.NCOLM 설명, `App_sub.c:562` 주석).

### 3.6 PLCA와 함께 쓰는 보조 설정
| 레지스터.비트 | 샘플 값 | 왜 필요한가 |
|---|---|---|
| T1STWEAKS.NCOLM (bit1) | 1 (`App_sub.c:562`) | PLCA가 돌 때는 충돌이 원래 없으므로 **충돌 표시를 가림**. PST=0이면 이 비트와 무관하게 충돌 검출 유지 |
| T1STWEAKS.RXDLY (bit0) | 1 (`App_sub.c:563`) | PLCA 모드에서 MII TX와 RX가 겹치지 않게 **RX를 늦춤** |
| T1SPLCAEXT.PREN (bit15) | 0 (`App_sub.c:570`) | 1이면 CAN처럼 "낮은 ID 우선(strict precedence)" 비표준 모드. 0 = 표준 라운드로빈 |
| T1SPLCAEXT.LDEN/LDR (bit1/0) | 0/0 (`App_sub.c:572-573`) | 1이면 ID와 상관없이 리더 강제 지정. 0 = **ID 0이 리더** (표준) |

## 4. 타이밍 다이어그램 (샘플 설정값 기준)

설정: NCNT = 9 (ID 0~8), TOTMR = 32 BT, MAXBC = 0, 실제 노드는 ID 0(코디네이터)과 ID 1 두 개.
1 BT = 100 ns. BEACON 길이는 IEEE 802.3cg 기준 약 20 BT로 표시했습니다 (UM에 숫자가 없어 표준값 기준).

### 4.1 아무도 보낼 게 없을 때 (빈 사이클)

```
시간 ──────────────────────────────────────────────────────────────────────►

선로   ▐BEACON▌ ·  ·  ·  ·  ·  ·  ·  ·  · ▐BEACON▌ ·  ·  ·
        (ID 0)
curID  ─────── │ 0 │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ 7 │ 8 │───────
               │32 │32 │32 │32 │32 │32 │32 │32 │32 │   (단위 BT)
               └─────────── 9 × 3.2 µs = 28.8 µs ───┘

한 바퀴 ≈ BEACON(~2 µs) + 28.8 µs ≈ 30.8 µs
```

### 4.2 ID 0과 ID 1이 각각 프레임 1개씩 보낼 때

```
시간 ──────────────────────────────────────────────────────────────────────►

선로   ▐BEACON▌▐═══ ID0 프레임 ═══▌ ▐═══ ID1 프레임 ═══▌ · · · · · · · ▐BEACON▌
curID  ─────── │  0 (TO 안에서 송신 시작)│  1               │2│3│4│5│6│7│8│
               └ 3.2 µs 안에 시작하면   └ ID0 끝나면 바로 ID1 차례
                 그 프레임 끝까지 ID0 차례                    └ 빈 TO 7개 = 22.4 µs

ID0 프레임: 헤더14 + 페이로드56 + FCS4 + 프리앰블/SFD 8 = 82 B ≈ 656 BT ≈ 65.6 µs
```

핵심 규칙 3개:
1. **내 TO가 시작되고 TOTMR(3.2 µs) 안에 송신을 시작하면**, TO는 프레임이 끝날 때까지 늘어납니다 (TO 길이는 가변).
2. 3.2 µs 동안 아무 신호가 없으면 **다음 ID로 자동으로 넘어갑니다.** 모든 노드가 선로를 보고 같은 curID를 셉니다.
3. `curID`가 NCNT(9)에 닿으면 코디네이터가 **다음 BEACON**을 보냅니다.

### 4.3 버스트 모드를 켰다면 (MAXBC=2 예시, 샘플은 0)

```
선로   ▐BEACON▌▐═ ID0 #1 ═▌ ▐═ ID0 #2 ═▌ ▐═ ID0 #3 ═▌ ▐═ ID1 ═▌ · · ·
                           └ BTMR(12.8 µs) 안에 다음 프레임이 오면 같은 TO 안에서 이어 보냄
```

## 5. 샘플 설정을 이해했을 때 보이는 튜닝 포인트

| 항목 | 현재 | 제안 | 이유 |
|---|---|---|---|
| NCNT | 9 (`App_sub.c:616`) | **실제 노드 수(예: 2)** | 노드가 2개인데 9로 두면 매 사이클 빈 TO 7개(22.4 µs)를 버림. 최악 대기 시간도 늘어남 |
| PLCATOTMR | 미설정(32 BT) | 필요 시 명시적으로 쓰기 | 모든 노드가 같아야 하므로, 리셋값에 기대기보다 코드에 명시하는 편이 안전 (FuSa 관점: 설정값 리드백 검증 가능) |
| PLCABURST | 미설정(버스트 끔) | 한 노드가 연속 프레임을 많이 보내면 MAXBC 검토 | 샘플처럼 프레임 4개를 보내면 지금은 4바퀴가 걸림 |
| PLCAST.PST | 안 읽음 | 초기화 끝에 **PST=1 확인** 추가 | STATUS는 링크 상태일 뿐, PLCA 동기 여부는 PST로 봐야 함 |
| 설정 순서 | EN=1(`:603`) 후 ID/NCNT(`:624`) | **ID/NCNT 먼저, EN 나중** 권장 | EN을 켠 순간에는 ID가 리셋값(0xFF)인 상태. 짧은 구간이지만 역할이 확정되기 전에 PLCA가 켜짐 |
| APP_COM_TYPE | 항상 MASTER (`App_ETNF_cfg.h:69,71`) | 보드별로 빌드 옵션 분리 | 두 보드를 같은 이미지로 올리면 코디네이터가 2개가 됨 |
| 폴링 루프 | 타임아웃 없음 (`:550-552`, `:635-637`) | 타임아웃 + 에러 보고 | 링크가 안 올라오면 영원히 대기 |

## 6. 확인하지 못한 것
- `ETNF_rPLCA_STATUS_REG_DONE`의 정확한 비트 마스크와 `ETNF_PLCA_ADDR_DEFAULT` 값은 `R_driver_ETNF.h`에 있습니다. 이 문서에서는 파일 줄 번호까지 확인하지 않았습니다. 이전 코드 리뷰(`docs/ETNF_10BASE-T1S_Code_Review.md` 3.3절)에 따르면 STATUS의 LNOK·ANAB·LKST·EXTC 4비트, PHY 주소 2입니다.
- BEACON의 정확한 길이는 UM에 숫자로 나와 있지 않아 IEEE 802.3cg 표준값(약 20 BT)을 썼습니다.
- 이전 코드 리뷰는 `APP_COM_MODE = AVB_LB`로 적었지만, 이번 Drive 업로드본은 `APP_ETNF_NORMAL`(`App_ETNF_cfg.h:58`)입니다. 이 문서는 업로드본을 기준으로 했습니다.
